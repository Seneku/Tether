# UE 5.9 Preview: what it means for Tether

Status: analysis, 2026-11-09. It comes from reading the 5.9 Preview source at `C:\Program Files\Epic Games\UE_5.9` (CL 60351404), diffing it against 5.8, and reading the announcement and release notes. The same day, it was checked against a live 5.9 editor on `D:\Projects\Unreal\TetherUE59` (§0). Items still marked **[run]** were not tested. Epic labels Unreal MCP, Unreal Assistant and Unreal Canvas Experimental, and this Preview had about a week of development.

## 0. Measured on a live 5.9 editor (2026-11-09)

The test project was `TetherUE59`: Blueprint-only, made with `ue new project --engine 5.9` and run on Tether 0.36.5 as it is on main.

- **Boot:** `ue open --headless --render` was ready in 52.3 s cold and 18.7 s warm, with 0 boot errors. `ue status`, PIE, perf, trace, gpu, film, `pie --clients 2`, the world tools, materials, foliage, import and tests all work unchanged.
- **`ue selftest`: 113 passed, 7 failed, 16 skipped in 100 s.** Every failure traces to an item below:

| Check | Error | Item |
|---|---|---|
| `call tether.level_summary` | `Unknown tool: describe_toolset` | B1 |
| `bp edit add-var`, then `class (Blueprint)` | `'blueprint' is ambiguous: WidgetBlueprintEditorSubsystem, LevelSequenceEditorBlueprintLibrary, NiagaraToolset_Blueprint` | B5 |
| `shot`, `look` | `Unknown tool CaptureViewport` | B4 |
| `shot --at` (PIE spectator) | the Slate screenshot came back empty | B9 |
| `fab settings` | `not found: /Script/Fab.Default__FabSettings` | B8 |

- **B2 confirmed.**
  - The old settings path returns None. The new one works, with the same property names.
  - **5.9's `BaseEditorPerProjectUserSettings.ini` sets `bAutoStartServer=True`**, although the C++ default is false. So every editor opens an MCP server on **:8000** unless told otherwise, and two user-opened editors collide there.
  - Fixing B2 makes the beacon report that port. Tether should also steer user-opened editors to its per-project port, as it already does when nothing is running.
- **B3 confirmed.** A stale cached session gets a bare 404 with `content-length: 0`. `ue actors` then printed nothing and **exited 0**. Deleting `Saved/Tether/mcp-session-<pid>.json` fixes it.
- **Discovery is bigger, not smaller.**
  - `list_toolsets` is 19 KB with `ue init`'s plugins (13 KB on 5.8), and 23 KB / 75 toolsets once 8 more toolset plugins are enabled. Engine subsystems and function libraries now register as toolsets, for example 13 `SequencerScripting.*Extensions` and `PCGEditor.PCGEditorSubsystem`.
  - Some descriptions span several lines and contain `- Graph:` bullets. Tether's catalog regex only accepts dotted names, so it skips them.
  - `describe_toolsets` without schemas: EditorAppToolset 9.9 KB, SceneCaptureToolset 7.0 KB. With schemas: 34.8 KB and 73.1 KB. One-tool `describe_tools` calls are the cheap path.
- **Strict schemas persist.** `ListModes` and `CaptureActiveEditorView` reject `{}` because their optional fields are marked required.
- **Blueprint DSL:**
  - Epic's Python `read_graph_dsl` now refuses plain Blueprints ("use the BlueprintDslToolset tools"). It serves Widget, Anim and level-script Blueprints only.
  - `BlueprintToolsets.BlueprintDslToolset.Read` answered in 0.04 s with DSL plus a `revision` token, and **left the Blueprint clean** (0 unsaved after the read).
  - It needs the `BlueprintToolsets` plugin, which `ue init` doesn't enable yet.
- **SceneCapture works from the editor and in PIE:**
  - `CaptureEditorViewport`: 0.09 s, 542 KB PNG, as an MCP image block.
  - `CaptureGameViewport` on the PIE world: 0.11 s, against `ue shot`'s 1.34 s on 5.8.
  - `Capture` (offscreen, Wireframe, 640x360): 6.3 s on its first call (shader warm-up), then fast.
  - `ListWorlds` names the editor and PIE worlds with `bCanCapture`.
- **Other new tools, first calls:**
  - `PerfToolset.StatsToolset.GetFrameTimings`: 0.03 s; frame, game, render, RHI and GPU ms.
  - `ConsoleToolset.RunConsoleCommand("stat unit")` returned only `["Cmd"]`, so console output capture is thin for stat commands.
  - `InputToolset.ApplyInput` validates entries ("zero Value, which has no effect"). It was not exercised further: there is no input fixture outside Sandbox.
- **Instance registry correction:** `%LOCALAPPDATA%/UnrealEngine/Instances/` is only written by `-AgentMode` runs (`RunResult.cpp` initializes it). An MCP-serving editor does not write one.
- **Not tested:** `-AgentMode`, the modal dialog pump, Unreal Assistant/ACP, Live Coding (Blueprint-only project), UnrealSharp, Perforce, audio.

Epic calls 5.9 "the first Unreal Engine release built primarily with agentic workflows". The agent surface roughly doubles: about 25 new toolsets, access-mode tags on every C++ tool, async and image tool results, Markdown skills served over MCP, an engine-level `-AgentMode`, and an `Extras/AgentTools` kit. Several of Tether's gaps over Epic's MCP are closed, and some of Tether's own calls break.

Checked and **compatible**:

- The "Starting MCP server on port N" log line is unchanged.

## 2. What changes behaviour

- **Modal dialogs no longer hang MCP.** The new `ModelContextProtocolModalDialogPump` keeps the server ticking through Slate modals, native modals and slow tasks (`MessageBoxExt` is not covered).
  - While one is up, `tools/call` returns `isError` with "Not run: the Unreal Editor is showing a modal dialog..." or a slow-task variant.
  - Tether's timeout-then-name-the-dialog path (`cli.py:1128`, `transport.py:249`, `core.py:819`) will stop firing. Map the new message to the same "blocked by modal" report and keep the watchdog for `MessageBoxExt`.
  - A second session's calls are now refused while another call runs a slow task.
- **`-AgentMode` / `UE_AGENT_MODE=1`** (engine-level, `Core/Public/Misc/AgentMode.h`):
  - It implies `-unattended -nosplash -nopause`, plus `-RenderOffScreen` (unless `-nullrhi`), `-JsonStdOut` and `-FullStdOutLogOutput`.
  - Message boxes return their default instead of showing, and it writes `UE_RUN` markers and a result file.
  - This is the no-popup guarantee Tether has been building by hand. Measure whether `ue open --headless` should pass it [run]. One caveat: `-unattended` disables UnrealSharp hot reload, which is why Tether uses `-RUNNINGUNATTENDEDSCRIPT` today.
- **Instance registry.** Agent-mode processes write `%LOCALAPPDATA%/UnrealEngine/Instances/<pid>.json`: kind, project, log path, ready flag, and the MCP and console ports. Measured: an ordinary MCP-serving editor does not write one, so this only helps if Tether launches with `-AgentMode`.
- **MCP auto-start is on by default** (measured): `BaseEditorPerProjectUserSettings.ini` sets `bAutoStartServer=True`, so user-opened editors serve on :8000.

## 4. Unreal Assistant + Claude Code

The in-editor Assistant's external-agent mode speaks **ACP** (Agent Client Protocol); it does not open a terminal.
- **Presets:** for Claude Code it runs `claude-agent-acp` (`npm i -g @agentclientprotocol/claude-agent-acp`); Codex, Cursor and OpenCode have presets too.
- **MCP handover:** it gives the agent the live MCP server URL, so Tether's toolset rides along.
- **Gotchas for Tether:**
  - The agent runs in the **editor's working directory, not the project's**, so project `CLAUDE.md`, `.claude/` and plugins may not load. Check with [run]. O1 (skills over MCP) is the way around it.
  - Its agent-undo buffer only wraps calls made from the panel's own tool path. Calls over MCP, Tether's included, are not captured, so `ue undo` stays Tether's own.
  - "Tool access mode" is enforced by the front end only, using the `accessMode` annotation (O2).

## 5. Where Tether's edge stands

5.9 closes several gaps listed in DESIGN §5.1:
- **Python:** unrestricted Python (`PythonScriptingTools.execute_python`, async, with `search_symbols`/`get_symbol` for API lookup)
- **Console:** console commands with output (`ConsoleToolset.RunConsoleCommand`)
- **Modal dialogs:** no more hangs (the dialog pump)
- **Images:** returned as real image content
- **Long calls:** async tools with cancellation
- **Undo:** undo history
- **Server start:** the MCP server starts automatically
- **Playtests:** input injection and runtime capture

What 5.9 still lacks, and Tether keeps:
- compact output (discovery was 79–101 KB against 13–40 KB)
- editor lifecycle (`build --restart`, close/reopen, crash handling)
- compile errors that name file and line (LiveCodingToolset still scrapes UBT's log; [run] whether that is fixed)
- leases and multi-session safety
- the Perforce guard
- UnrealSharp C# reload
- scripted playtests (`pie do`, watch, record)
- packaging and boot tests
- lint, budgets and CI

**Re-run COMPARISON on 5.9** once B1–B5 are fixed. Epic's discovery cost may have dropped (`describe_toolsets` without schemas), and its T4 compile-error result may have changed.
